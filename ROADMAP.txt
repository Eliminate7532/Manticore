PHASE 2B - Rules Depth via Forge Integration (revised direction)
-----------------------------------------------------------------------
DECISION: Rather than reimplementing a full MTG rules engine from scratch
in Python, use Forge (github.com/Card-Forge/forge), an existing open-source
GPL-3.0 Java rules engine with years of community development, as the
actual rules/gameplay backend. Our Python layer stays as the interface:
deck import, visual table, bug reporting, and orchestration.

Why: Forge already implements state-based actions, stack/priority,
replacement effects, and a working AI - the exact things Phase 2B would
have required building from zero. Forge supports a documented headless
simulation mode (the `sim` command-line flag) designed for exactly this
kind of external scripting/orchestration, and prior art exists for
Python-to-Forge bridges (e.g. projects wrapping Forge's headless AI-vs-AI
mode, including one with a full pipeline from Moxfield deck -> .dck file
-> real headless Forge game, and 4-deck pod batch runs).

[x] Sketched forge_bridge.py (Python wrapper around Forge's headless `sim`) - SUPERSEDED, not used. Forge's `sim`
    mode only runs whole AI-vs-AI games and cannot take a human's clicks.
[x] Built the real thing instead (2026-09-19): Forge is run as a Java process whose GUI interface (IGuiGame) is
    implemented by our own small bridge (java_bridge/src, ~1000 lines). It sends the whole game state as JSON
    lines and asks Forge's questions as "requests"; forge_client.py (Python) speaks that protocol and
    forge_table.py draws it. Forge decides everything about the rules.
[x] Forge built from source (commit 3a74143, 2.0.15-SNAPSHOT) and packed in forge_bundle/ with checksums;
    setup_forge.py unpacks it and runs a smoke game (python setup_forge.py --check)
[x] Verified in the cloud sandbox with real Forge + Java 21: whole games driven through the table code, including
    Gemstone Caverns before turn 1, mana payment, choices, discard, combat prompts, stack, stops. 366 tests pass (8 live)
[x] FIXED (2026-09-19): fetchland and other library/graveyard/exile searches were unusable - Forge asked to 'select a card
    from your library' on the board, where our table has no library to click. The bridge now switches Forge's
    UI_SELECT_FROM_CARD_DISPLAYS preference off so it sends a list instead (also fixes scry/surveil, tutors, recursion)
